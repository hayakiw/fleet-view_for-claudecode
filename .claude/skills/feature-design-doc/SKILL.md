# 設計提案の作り方

以下の構成で簡潔にまとめる。実装はしない。

## 1. 背景・目的
何を解決したいか、なぜ今必要か

## 2. 現状の制約
既存のアーキテクチャ・データモデル・依存関係のうち、この設計に影響するもの
（実際にコードを読んで確認する。推測で書かない）

## 3. 検討した選択肢
最低2案を挙げ、それぞれの利点・欠点を簡潔に

## 4. 推奨案
どれを推すか、その理由

## 5. 未解決の論点
実装前に確認・決定すべきこと

## 心がけること
- 既存コードを読み込んでから提案する
- 過剰設計を避け、今の要件に見合った規模にする
- コード自体は書かない・修正しない
