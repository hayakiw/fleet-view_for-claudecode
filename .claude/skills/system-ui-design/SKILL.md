# システム画面デザインの進め方

## 1. 理解する
- どんな画面か（一覧、詳細、フォーム、ダッシュボード等）、誰が・どんな頻度で使うかを確認する
- プロジェクト内に既存のUI（配色、余白、コンポーネントのパターン、既存画面）があれば
  実際に読み込んで踏襲する。勝手に新しいスタイルを持ち込まない
- 曖昧な場合は無理に進めず、不明点を報告する

## 2. 設計方針
- LPのような訴求性より、使いやすさ・分かりやすさ・情報の一覧性を優先する
- よくある状態を考慮する: データが多い場合／0件の場合／読み込み中／エラー時
- 入力フォームは、入力例・バリデーションエラー表示位置まで含めて設計する

## 3. 作る
- HTML/CSSは自己完結（インラインstyleまたは1ファイル内の`<style>`）にする
- レスポンシブ（最低限、極端に崩れないこと）を意識する
- アクセシビリティの基本（ラベルとフォーム要素の対応、十分なコントラスト）を守る

## 4. 確認する
- 空・大量データ・エラー状態でも破綻しないか
- 既存画面と配色・余白・フォントのトーンが揃っているか

## 5. コミットする
- 完成したら、内容が分かるメッセージでローカルgitにコミットする
- 明示的に指示されない限り push はしない
