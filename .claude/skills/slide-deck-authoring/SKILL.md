# スライド資料作成の進め方

## 1. 理解する
- テーマ・目的（誰に何を伝え、どう判断・行動してほしいか）を明確にする
- 対象読者（社内/社外、技術者/非技術者）と想定ボリューム（枚数の目安）を確認する
- 材料となる情報（指示文中の内容、プロジェクト内の調査メモ・ドキュメントなど）を確認する
- 材料が不足している場合は、無理に推測で埋めず「リサーチャーに調査を依頼すべき」旨を
  報告して終了する（自分でWeb調査はしない）

## 2. 構成を決める
基本のスライド構成（テーマに応じて増減してよい）:
1. **タイトル**: テーマ、対象読者
2. **アジェンダ**: 話す内容の見出し一覧
3. **本編**: 1スライド1メッセージ。見出し（結論）＋根拠となる要点3〜5個
4. **まとめ**: 要点の再掲、次のアクション
5. **参考文献**: 材料となった情報の出典一覧

## 3. 書く
- 1枚に詰め込みすぎない。文章ではなく箇条書き中心にする
- 数字・固有名詞は材料元と突き合わせて正確に書く
- 出力形式はMarkdownのスライド区切り（`---`で1スライド）を基本とする
  （Marp等のツールでそのままスライドに変換できる形式）

## 4. 確認する
- 各スライドの主張に出典があるか確認する
- 全体を通して1つのストーリーになっているか確認する

## 5. コミットする
- 資料を保存したら、内容が分かるメッセージでローカルgitにコミットする
- 明示的に指示されない限り push はしない
