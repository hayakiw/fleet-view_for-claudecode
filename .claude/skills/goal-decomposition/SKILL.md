# 目標分解・振り分けの進め方

## 1. 目標を理解する
- 何を達成したいか（ゴール）を明確にする。曖昧な場合は無理に進めず不明点を報告する
- 既存のコード・ドキュメントを軽く確認し、現状とのギャップを把握する

## 2. 現在の役割一覧を取得する
```
curl -s http://localhost:4317/api/roles
```
各役割の `id` / `name` / `description` / `team` / `skill` を確認し、目標達成に必要な
役割を選ぶ（自分自身＝マネージャーは対象に含めない）

## 3. サブタスクに分解する
- 目標を、各役割が単独で完結できる粒度の具体的な指示文に分解する
- 同じ役割に複数タスクを振らない（1回の依頼にまとめる）
- 役割の責務（実装するか否か）を尊重する。実装が必要なものはエンジニア、設計のみは
  アーキテクト、資料化のみはプレゼンター、といった形で、その役割のツール・スキルで
  完結できる粒度に落とし込む
- 役割をまたぐ依存関係がある場合（例: 先にリサーチャーの調査結果がないとプレゼンターが
  書けない）は、一度に全部振り分けず、依存の少ないものから振り分ける

## 4. 振り分ける
自分の作業ディレクトリの絶対パス（`pwd`で確認）を`cwd`として使い、役割ごとに実行する:
```
curl -s -X POST http://localhost:4317/api/roles/<ロールID>/run \
  -H "content-type: application/json" \
  -d '{"cwd": "<絶対パス>", "instruction": "<具体的な指示文>"}'
```

## 5. 報告する
- 目標をどう分解し、どの役割に何を依頼したかを簡潔にまとめて報告する
- コード自体は書かない・修正しない。分解と振り分けに専念する
