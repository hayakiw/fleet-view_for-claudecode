# コードレビュー手順

以下の観点を順に確認し、見つけた指摘は重大度順にまとめて報告する。

## 1. 正確性
- ロジックが意図通りか。エッジケース（空・null・境界値・並行処理）は考慮されているか
- 既存の挙動を壊していないか

## 2. セキュリティ（脆弱性診断）
- **インジェクション**: ユーザー入力がそのままSQL/シェルコマンド/HTMLに渡っていないか
  （SQL/コマンド/パス/テンプレートインジェクション、XSS）
- **認証・認可**: チェック漏れ、他人のリソースへの不正アクセスの余地はないか
- **機密情報の扱い**: APIキー・パスワード・トークンのハードコードやログ出力、平文保存
- **入力値の検証**: ユーザー入力の検証・サニタイズ漏れ
- **依存関係**: 既知の脆弱性を持つ依存パッケージ（package.json等のバージョンを確認）
- **通信・設定**: 不必要に緩いCORS設定、デバッグ設定の本番混入、安全でない通信
- 見つけた問題は「どこに・なぜ危険か・想定される悪用シナリオ」を具体的に示し、
  緊急度の目安（Critical/Warning等）を添える
- 確証のない懸念は「疑わしい点」として、確定した脆弱性と区別して報告する

## 3. エラーハンドリング
- 失敗しうる処理（外部呼び出し、パース、I/O）に適切な処理があるか
- エラーメッセージが内部情報を過剰に露出していないか

## 4. テスト
- 変更箇所に対応するテストがあるか、既存テストは通るか

## 5. 一貫性・簡潔さ
- 既存のコード規約・命名に沿っているか
- 不要に複雑になっていないか

## 報告の仕方
- 重大度（Critical / Warning / Nit）ごとに分類する
- 該当ファイル・行を明示する
- 指摘のみ行い、指示がない限りコード自体は修正しない
